## What a project is

A project is the home for a body of work in Toone. It keeps the people-facing name of the work together with the agents, routines, tools, files, and context used to carry it out.

Each project contains its own set of agents, MCP servers, routines, and context. Nothing leaks between projects, so what you set up for one body of work stays available there and does not clutter the others.

## Create the project

Click the **+** at the top of the window and choose an empty folder. Toone takes care of the rest: it scaffolds the project inside that folder, and from then on everything the project's agents produce lives there.

The folder name becomes the project name, so pick it with the scope in mind.

## Choose a useful scope

A project is a boundary around related work, and the name is how you draw it. Two shapes work well:

- **A focused subset**, such as **acme.com growth**. Everything inside is about growing that site: the agents, the routines they run, and the context they build up. Other work on acme.com, such as support or engineering, gets its own project.
- **Something more general**, such as **acme.com**. One project holds all the work around the site, and agents specialize within it as it grows.

Both work. Start with whichever matches how you think about the work today; you can always create another project later when a subset earns its own space.

Avoid designing a large system at this stage. One clear boundary is enough to expose the whole operating loop.

## Checkpoint

Open the project and confirm that you can reach its Agents and Routines panels. An empty project is expected; you will add the first agent next.
