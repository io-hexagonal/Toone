## See when work is supposed to happen

The Calendar places scheduled routines and ordinary project events on the same time-based surface. Move between day, week, and month views depending on the planning horizon you need.

```toone-ui
calendar-week
```

## Routine schedules

Scheduled routines appear as read-only events derived from their routine definitions. This makes the operating schedule visible without turning Calendar edits into silent changes to a routine.

```toone-ui
calendar-routine-event
```

## Project events

Create and edit project events directly in the Calendar. Events can include timing, participants, tags, and confirmation status, while proposed events can remain pending until someone confirms them. In the Mac App Store edition, agents can't read or propose calendar events, so the events there are the ones you add.

```toone-ui
calendar-proposed-event
```

## Keep schedule and execution distinct

The Calendar explains when work is expected. Use the **Routines** panel and background threads to understand what is actively running and how it is progressing.

```toone-ui
routines-list-running
```
