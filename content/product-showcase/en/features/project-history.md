## A timeline for project changes

Project History presents Git-backed checkpoints through a visual Timeline inside Toone. It is designed to make changes understandable even when you are not working directly with Git commands.

## See what changed and who changed it

Timeline entries retain the checkpoint message, author identity, and affected project state. Agent attribution settings help distinguish automated changes from work attributed to you.

## Ask for an explanation

Open a checkpoint in context when the summary is not enough. The surrounding conversation can help explain what changed and why before you decide what to do next.

## Set it up when the project is ready

Project History depends on a Git repository and identity configuration. The Timeline and Settings both expose setup when those prerequisites are missing; remote GitHub automation is optional.
